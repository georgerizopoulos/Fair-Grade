# API Spec

The contract between the backend and the frontend for the **course / exam / paper** flow. If you change an endpoint, update its section in the same commit and tell the team.

Each endpoint is marked **✅ built** (in the code, with tests where noted) or **⏳ planned** (agreed shape, not built yet).

---

## Conventions

- **Base URL:** `http://localhost:3001`, no `/api` prefix. The frontend reads it from `NEXT_PUBLIC_API_URL`.
- **CORS:** allowed from `http://localhost:3000`. The response headers `X-User-Role` and `X-User-Id` are exposed.
- **Format:** JSON in and out. File uploads are `multipart/form-data` with the file in the field `file`.
- **Auth:** every endpoint except `GET /health`, `POST /auth/login` and `POST /auth/register` needs `Authorization: Bearer <token>`.
  - Every authenticated response carries `X-User-Role: instructor|ta` and `X-User-Id`.
- **IDs:** UUID strings generated by the backend. Course and exam ids in URLs are these UUIDs, not codes.
- **Timestamps:** ISO 8601 UTC strings.
- **Points:** numbers in **0.5 steps**, from 0 to the question's `maxPoints`.
- **Roles:** always lowercase, `instructor` or `ta`.
- **People in lists:** the signed-in user's own row has `isYou: true`.
- **No pagination.** Every list comes back in full.

## Errors

Every error has this shape:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "answers[1].taPoints for Q2 must be 0 to 3 in steps of 0.5" } }
```

The `message` always names the field, id or question that is wrong.

| `code` | HTTP | When |
|---|---|---|
| `VALIDATION_ERROR` | 400 | missing or invalid field, or a rule that needs data (points over the max, rubric doesn't add up, missing points on submit) |
| `UNAUTHORIZED` | 401 | no token, bad or expired token, user deleted or `DEACTIVATED`, wrong email or password |
| `FORBIDDEN` | 403 | wrong role, not a member or owner of the course, not your paper |
| `NOT_FOUND` | 404 | an id that doesn't exist |
| `CONFLICT` | 409 | duplicate (email, course code, member, question code) or wrong state (grades locked, paper not submitted, AI still grading) |
| `LLM_FAILURE` | 502 | the AI call failed |
| `INTERNAL_ERROR` | 500 | anything unexpected |

## Who may do what

The backend enforces all of this (`AccessService` and `@Roles`). The UI only mirrors it.

| Action | Instructor (course owner) | TA (course member) | TA (not a member) |
|---|---|---|---|
| See the course and its exams | yes | yes | 403 |
| Create or edit exams and questions | yes | 403 | 403 |
| Manage users and course members | yes | 403 | 403 |
| Add, edit or submit a paper | upload only, for a TA | own papers only | 403 |
| See a paper | every paper in the course | own only | 403 |
| See the AI grade of a paper | always | own, after submit | 403 |
| Reopen a paper | yes | request only | 403 |
| Exam report and per-TA page | yes | 403 | 403 |
| Own stats (`my-stats`, `my-papers`) | 403 | yes | 403 |

**Further rules:**
- **Membership is the only thing that gives a TA access.** Removing a member keeps their submitted papers, which still count in reports.
- An instructor sees the courses they own. Legacy courses with no owner are visible to every instructor.

## Data model

Prisma schema: `backend/prisma/schema.prisma`, SQLite.

```
User          id, name, email (lowercase, unique), passwordHash, role (instructor|ta),
              status (ACTIVE|INVITED|DEACTIVATED), lastSignInAt, createdAt
Course        id, code (unique), name (unique), semester, ownerId → User,
              leaderboardVisibility (OFF|ANONYMOUS|NAMED, default ANONYMOUS)
CourseMember  (courseId, userId) unique, role, addedAt
Exam          id, courseId, name, heldAt, status (DRAFT|QUESTIONS_READY|OPEN|PUBLISHED), passMark (default 5)
Question      id, examId, code (Q1… unique per exam), title, prompt, maxPoints, modelAnswer, order
RubricPoint   id, questionId, text, points, order          (points add up to the question's maxPoints)
Paper         id, examId, taId, studentId ((examId, studentId) unique), pdfPath, pageCount,
              status (TRANSCRIBING|DRAFT|AI_GRADING|AI_GRADED|AI_FAILED), reopenRequested,
              aiAttempts, aiNextAttemptAt, aiError, createdAt, submittedAt, aiGradedAt
PaperPage     (paperId, index), status (WAITING|READING|READ|UNREADABLE)
PaperAnswer   (paperId, questionId), transcription, uncertainWords (json string[]), pages (json int[]),
              taPoints, aiPoints, aiReasoning
PaperRevision id, paperId, taPointsSnapshot (json {questionId: points}), createdAt, createdBy
ActivityLog   id, courseId, type, actorId, paperId?, payload (json), createdAt
```

`ActivityLog.type` is one of: `PAPER_DRAFT_SAVED`, `PAPER_SUBMITTED`, `AI_GRADED`, `AI_FAILED`, `TA_FLAGGED`, `MEMBER_ADDED`, `MEMBER_REMOVED`, `PAPER_REOPENED`, `REOPEN_REQUESTED`.

### Paper lifecycle

```
TRANSCRIBING → DRAFT ──submit──▶ AI_GRADING ──worker──▶ AI_GRADED
                 ▲                   │                     │
                 │                   └──worker──▶ AI_FAILED ──retry-ai──▶ AI_GRADING
                 └──────────── reopen (instructor) ◀───────┘
```

- **`DRAFT`:** the TA edits transcriptions and points. Nobody else can.
- **Submit:** needs points on every question. It locks the TA's points, sets `submittedAt`, and queues the paper for the AI.
- **The AI worker** (`backend/src/ai/`, ✅ built):
  - every 2 s picks papers with `status = AI_GRADING` and `aiNextAttemptAt <= now` (3 at a time);
  - grades each question with one LLM call (prompt `ai/prompts/grade-question.v1.ts`, temperature 0), clamps the points to 0…max in 0.5 steps and keeps at most two sentences of reasoning;
  - writes `aiPoints` and `aiReasoning` only while the paper is still `AI_GRADING`;
  - tries 3 times (waiting 5 s, then 20 s), then sets `AI_FAILED` with `aiError`;
  - writes `AI_GRADED` / `AI_FAILED` activity, and `TA_FLAGGED` the first time a TA crosses the flag threshold on a question;
  - logs every call (prompt version, model, latency) without student data. `AI_WORKER=off` in `.env` stops it.
- **Reopen:** goes back to `DRAFT`, clears `submittedAt`, and writes a `PaperRevision` with the TA's points. The AI grade is kept and re-run on the next submit.
- **Metrics** count only `AI_GRADED` papers.

### Gaps and flags

The same rule is used everywhere:
- **gap** = TA points − AI points. Negative means the TA was stricter.
- **paper gap** = the sum of the gaps over the questions.
- **A TA is flagged on a question** when they have at least 3 papers on it and `|average gap| > 0.15 × maxPoints`.

## Health and auth

### `GET /health` ✅

Returns 200 even when the database is down, so the UI can say which part is broken.

```json
{ "status": "ok", "database": "ok" }
```

`database` is `"error"` when the database can't be reached.

### `POST /auth/login` ✅

Request:

```json
{ "email": "nikos@demo.com", "password": "demo1234" }
```

Response (200):

```json
{ "token": "eyJ…", "user": { "id": "…", "name": "Nikos Georgiou", "email": "nikos@demo.com", "role": "ta" } }
```

- The email is matched case-insensitively.
- The JWT payload is `{ sub, role, name }` and it is valid for 24 h.
- Signing in sets `lastSignInAt` and turns an `INVITED` user into `ACTIVE`.
- A wrong email, a wrong password and a `DEACTIVATED` user all get the same 401.

### `GET /auth/me` ✅

Response: `{ id, name, email, role }`. Returns 401 if the user was deleted (e.g. after re-seeding) or deactivated.

### `POST /auth/register` ✅ (development only, off by default)

Request: `{ name, email, password (min 6), role }` → 201 with the user. Returns 409 if the email exists.

It is public and lets the caller pick any role, so it returns **403** unless `ALLOW_REGISTER=on` is set in `backend/.env`. The app creates accounts through `POST /users` instead.

## Users (instructor only)

### `GET /users?role=instructor|ta` ✅

```json
{
  "viewerRole": "instructor",
  "users": [
    {
      "id": "…", "name": "Maria Papadaki", "email": "maria@demo.com", "role": "ta",
      "status": "ACTIVE", "lastSignInAt": "2026-10-01T11:05:00Z", "createdAt": "…",
      "courses": [{ "id": "…", "code": "HY335" }],
      "isYou": false
    }
  ]
}
```

- Sorted by name.
- `courses` lists the courses an instructor owns or a TA is a member of.

### `POST /users` ✅

Request:

```json
{ "name": "Alexandros Kostakis", "email": "alexandros@demo.com", "role": "ta", "mode": "invite" }
```

| `mode` | Body | Result |
|---|---|---|
| `"password"` | needs `password` (min 6) | status `ACTIVE` |
| `"invite"` | no password | status `INVITED`; a password is generated and returned **once** as `temporaryPassword` |

Response (201): the user (same fields as in the list, minus `courses` and `isYou`), plus `temporaryPassword` when `mode` is `"invite"`.

Errors:
- 400 for a bad field, or a missing password with `mode: "password"`;
- 409 if the email exists.

### `PATCH /users/:id` ✅

Request: any of `{ name, email, role, status: "ACTIVE" | "DEACTIVATED" }`. Response: the user.

- **`DEACTIVATED`:** the user can't sign in and their token stops working. Their papers still count.
- **Reactivating:** someone who never signed in goes back to `INVITED`.

Errors:
- 400 if you deactivate yourself or drop your own instructor role;
- 404 for an unknown user;
- 409 if the new email is already used.

## Courses and members

### `GET /courses` ✅

An instructor gets the courses they own. A TA gets only the courses they are a member of.

```json
{
  "viewerRole": "ta",
  "courses": [
    {
      "id": "…", "code": "HY335", "name": "Computer Networks", "semester": "Winter 2026–27",
      "examCount": 5, "taCount": 5,
      "latestExam": { "id": "…", "name": "Resit", "status": "DRAFT", "heldAt": "2027-09-10T00:00:00Z" }
    }
  ]
}
```

Sorted by code. `latestExam` is the exam with the latest date.

### `POST /courses` ✅ (instructor)

Request: `{ code, name, semester }`. The caller becomes the owner.

Response (201): same shape as `GET /courses/:id`. Returns 409 if the code or name already exists.

### `GET /courses/:id` ✅ (owner or member)

```json
{
  "viewerRole": "instructor",
  "id": "…", "code": "HY335", "name": "Computer Networks", "semester": "Winter 2026–27",
  "leaderboardVisibility": "ANONYMOUS",
  "owner": { "id": "…", "name": "Instructor Demo", "isYou": true },
  "exams": [
    {
      "id": "…", "name": "Midterm", "heldAt": "…", "status": "OPEN", "passMark": 5, "questionCount": 3,
      "progress": { "papers": 58, "drafts": 0, "submitted": 58, "aiGrading": 1, "aiGraded": 57, "aiFailed": 0 }
    }
  ],
  "members": [
    { "userId": "…", "name": "Maria Papadaki", "email": "…", "role": "ta", "addedAt": "…", "isYou": false }
  ]
}
```

Exams are sorted by date, and exams with no date come last. In `progress`, `drafts` counts `TRANSCRIBING` + `DRAFT`, and `submitted` counts `AI_GRADING` + `AI_GRADED` + `AI_FAILED`.

### `PATCH /courses/:id/settings` ✅ (owner)

Request: `{ "leaderboardVisibility": "OFF" | "ANONYMOUS" | "NAMED" }`. Response: `{ id, leaderboardVisibility }`.

### `GET /courses/:id/members` ✅ (owner or member)

```json
{
  "viewerRole": "instructor",
  "owner": { "userId": "…", "id": "…", "name": "Instructor Demo", "email": "…", "status": "ACTIVE", "isYou": true },
  "members": [
    {
      "userId": "…", "name": "Maria Papadaki", "email": "maria@demo.com", "status": "ACTIVE",
      "role": "ta", "addedAt": "…", "papersGraded": 12, "isYou": false
    }
  ]
}
```

`papersGraded` counts the TA's submitted papers in this course.

### `POST /courses/:id/members` ✅ (owner)

Request, in one of two forms:
- `{ "userId": "…" }` adds an existing TA;
- `{ "name": "…", "email": "…", "password"?: "…" }` creates a TA account and adds it. With a password it is `ACTIVE`; without one it is an invite, `INVITED`, with a generated password.

Response (201): `{ userId, name, role: "ta", temporaryPassword? }`. Writes a `MEMBER_ADDED` activity entry.

Errors:
- 400 if the user is an instructor, or `name`/`email` is missing;
- 404 for an unknown `userId`;
- 409 if the user is already a member or the email exists.

### `DELETE /courses/:id/members/:userId` ✅ (owner)

Response: `{ removed: true, userId }`. Writes a `MEMBER_REMOVED` activity entry. Returns 404 if the user is not a member.

## Exams and questions (course owner)

### `GET /courses/:id/exams` ✅

Response: `{ courseId, exams: [{ id, name, heldAt, status, questionCount, paperCount }] }`, in date order.

### `POST /courses/:id/exams` ✅

Request: `{ name, heldAt? }`. Response (201): same shape as `GET /exams/:id`. A new exam starts as `DRAFT`.

### `GET /exams/:id` ✅

Response: `{ id, name, heldAt, status, passMark, courseId, course: { id, code, name }, questionCount, paperCount }`.

### `PATCH /exams/:id` ✅

Request: any of `{ name, heldAt (null clears it), passMark, status }`. Response: same shape as `GET /exams/:id`.

Status flow: `DRAFT` → `QUESTIONS_READY` (set automatically by the first `PUT /exams/:id/questions`) → `OPEN` (TAs see it and add papers) → `PUBLISHED` (no new papers), and back to `OPEN` to reopen.
- 400 when opening or publishing an exam without questions;
- 409 when moving an exam that already has papers back to `DRAFT` or `QUESTIONS_READY`.

### `GET /exams/:id/questions` ✅

```json
{
  "examId": "…",
  "questions": [
    {
      "id": "…", "code": "Q1", "title": "TCP three-way handshake",
      "prompt": "Explain how the TCP three-way handshake works.",
      "maxPoints": 4, "modelAnswer": "The client sends SYN…", "order": 1,
      "rubric": [{ "id": "…", "text": "Names the three steps in order", "points": 2, "order": 1 }]
    }
  ]
}
```

### `PUT /exams/:id/questions` ✅

Saves every question at once. The order of the array becomes `order`.

```json
{
  "questions": [
    {
      "code": "Q1", "title": "…", "prompt": "…", "maxPoints": 4, "modelAnswer": "…",
      "rubric": [{ "text": "Names the three steps in order", "points": 2 }]
    }
  ]
}
```

- Questions are matched **by `code`**: existing codes are updated, new codes are created, and missing codes are deleted.
- Each question's rubric is replaced.
- Response: same shape as `GET /exams/:id/questions`.

Errors:
- 400 `Q1: rubric points add up to 3, not 4`;
- 400 if a question code appears twice;
- 409 if you delete a question that papers already use.

### `POST /exams/:id/questions/import` ✅

Multipart with `file` = a solutions PDF.

Response: `{ examId, questions: [ … draft questions in the PUT shape … ] }`. **Nothing is saved**: the instructor reviews the drafts and then calls `PUT`. Returns 400 if the file isn't a PDF.

## Papers

### `POST /exams/:id/papers` ✅

Multipart fields:
- `file`: one PDF, up to 20 MiB;
- `studentId`;
- `taId`: required when an instructor uploads on a TA's behalf. A TA always uploads as themselves.

What it does:
- creates the paper and one `PaperPage` per PDF page;
- one `PaperAnswer` per question;
- the transcription. **For now it is a demo fake**: `paper-transcriber.ts` fills in one of 5 ready-made transcriptions, with `uncertainWords` marked, and the paper starts in `DRAFT` with every page `READ`. A real vision model will replace it and the paper will start in `TRANSCRIBING`.

Response (201): same shape as `GET /papers/:id`.

Errors:
- 400 for a missing or invalid PDF, or a missing `taId` for an instructor;
- 404 if `taId` is unknown or not a TA;
- 409 if a TA adds a paper while the exam is not `OPEN`, or the `studentId` already has a paper in this exam.

### `GET /papers/:id` ✅

```json
{
  "viewerRole": "ta",
  "id": "…", "studentId": "csd5146", "status": "AI_GRADED", "reopenRequested": false, "locked": true,
  "createdAt": "…", "submittedAt": "…", "aiGradedAt": "…", "aiError": null, "pageCount": 4,
  "ta": { "id": "…", "name": "Nikos Georgiou", "isYou": true },
  "exam": { "id": "…", "name": "Midterm", "passMark": 5 },
  "course": { "id": "…", "code": "HY335", "name": "Computer Networks" },
  "pages": [{ "index": 0, "status": "READ" }],
  "answers": [
    {
      "questionId": "…", "code": "Q2", "title": "TCP and UDP", "prompt": "…", "maxPoints": 3,
      "modelAnswer": "…", "rubricPoints": [{ "text": "…", "points": 1.5 }],
      "transcription": "TCP is reliable, UDP is not…", "uncertainWords": [], "pages": [1],
      "taPoints": 1, "aiPoints": 2, "aiReasoning": "States the core difference…"
    }
  ],
  "maxTotal": 10, "taTotal": 7, "aiTotal": 8, "gap": -1
}
```

- **AI fields are hidden from a TA until submit.** For a TA on a `DRAFT` or `TRANSCRIBING` paper, `aiPoints`, `aiReasoning`, `aiTotal` and `gap` are left out, and `aiGradedAt` / `aiError` are `null`. The instructor always gets them.
- Answers follow question order.
- `taTotal` is `null` until every question has points. `aiTotal` and `gap` are `null` until every question has an AI grade.

### `PATCH /papers/:id` ✅ (the paper's TA, `DRAFT` only)

Saves the draft. Only the questions you send change. `taPoints: null` clears the points.

```json
{ "answers": [{ "questionId": "…", "transcription": "…", "taPoints": 2.5 }] }
```

Response: same shape as `GET /papers/:id`. It writes a `PAPER_DRAFT_SAVED` activity entry at most once per 10 minutes per paper, so autosave is safe.

Errors:
- 400 if a question isn't part of the exam, or the points aren't 0…max in 0.5 steps (the message names the question code);
- 403 if you're not the paper's TA;
- 409 with "Grades are locked after submit" or "still being transcribed".

### `POST /papers/:id/submit` ✅ (the paper's TA, `DRAFT` only)

No body. Locks the grades and queues the paper for the AI: `status` becomes `AI_GRADING`, `submittedAt` is set to now, attempts reset, and `reopenRequested` becomes `false`. Writes a `PAPER_SUBMITTED` activity entry.

Response: same shape as `GET /papers/:id`.

Errors:
- 400 `Give points for every question before submitting: Q2, Q3`;
- 400 if the exam has no questions;
- 409 if the paper is not `DRAFT`.

### `POST /papers/:id/pages/:index/rescan` ✅ (owner, or the paper's TA, `DRAFT` only)

Puts page `index` (0-based) back to `WAITING` for a re-read. Response: `{ paperId, index, status }`.

Returns 404 for an unknown page and 409 if the paper is not `DRAFT`. **Replacing the page file itself is ⏳ planned.**

### `POST /papers/:id/request-reopen` ✅ (the paper's TA)

Sets `reopenRequested: true`. Calling it again does nothing new. Writes a `REOPEN_REQUESTED` activity entry. Response: same shape as `GET /papers/:id`.

Returns 403 for an instructor (they reopen directly) and 409 if the paper isn't submitted.

### `POST /papers/:id/request-reopen` body ✅

Optional `{ "reason": "…" }` (max 500 characters), stored in the activity entry. `GET /papers/:id` returns `reopenRequest: { requestedAt, by: { id, name }, reason }` while a request is open.

### `POST /papers/:id/decline-reopen` ✅ (owner)

Clears the request and keeps the TA's grade. 409 if nobody asked. The TA can ask again.

### `GET /courses/:id/reopen-requests` ✅ (owner)

`{ requests: [{ paperId, studentId, status, ta, exam, requestedAt, reason, taTotal, aiTotal, gap, maxTotal }] }`, oldest first. `GET /courses` and `GET /courses/:id` (and each exam in it) also return a `reopenRequests` count for the instructor.

### `POST /papers/:id/reopen` ✅ (owner)

Allowed from `AI_GRADED` or `AI_FAILED`.

- Writes a `PaperRevision` with the TA's points.
- Sets `status: DRAFT`, `submittedAt: null`, `reopenRequested: false`.
- Keeps the AI grade.
- Writes a `PAPER_REOPENED` activity entry.

Response: same shape as `GET /papers/:id`. Returns 403 for a TA and 409 while the paper is `AI_GRADING` or not submitted.

### `POST /papers/:id/retry-ai` ✅ (owner, or the paper's TA)

Allowed only from `AI_FAILED`. Puts the paper back in the queue: `AI_GRADING`, attempts reset, error cleared. Response: same shape as `GET /papers/:id`. Returns 409 otherwise.

### `GET /exams/:id/my-papers?filter=all|drafts|submitted&q=` ✅ (TA member)

The signed-in TA's papers in this exam, newest first. `q` searches the student ID.

```json
{
  "examId": "…",
  "counts": { "all": 12, "drafts": 1, "submitted": 11, "aiGrading": 1, "aiGraded": 10, "aiFailed": 0 },
  "papers": [
    {
      "id": "…", "studentId": "csd5146", "status": "AI_GRADED", "createdAt": "…", "submittedAt": "…",
      "reopenRequested": false, "taTotal": 7, "aiTotal": 8, "gap": -1
    }
  ]
}
```

- `taTotal` is shown only for submitted papers.
- `aiTotal` and `gap` are shown only for `AI_GRADED` papers.
- `counts` ignores the filter.
- Returns 403 for instructors.

## Reports and stats

These count only `AI_GRADED` papers. The exact response types are in `backend/src/reports/reports.dto.ts`.

### `GET /exams/:id/my-stats` ✅ (TA member)

The TA's own numbers for one exam (type `MyStatsResponse`):
- `counts`: total, submitted, aiGraded, pending, drafts;
- `summary`:
  - TA vs AI average, average gap;
  - exact matches and within half a point;
  - median time per paper;
  - largest gap;
  - flagged question count;
- `paperComparisons`: TA/AI totals per paper, in grading order;
- `questions`: average gap per question, with the flag;
- `worthASecondLook`: the TA's largest single-question gaps, with the AI's reasoning;
- `leaderboard` and `badges`, which follow the course's `leaderboardVisibility`:
  - `OFF`: left out;
  - `ANONYMOUS`: other TAs appear as "TA 2", "TA 3" (their rank);
  - `NAMED`: other TAs appear with their names;
  - the score is the TA's average |paper gap| in this exam, smallest first.

The math (gaps, flags, totals) is in `backend/src/reports/report-math.ts`, shared by all three report endpoints.

### `GET /exams/:id/report/tas/:taId` ✅ (owner)

Type `TaDetailReportResponse`:
- the TA's summary: `papersGraded`, `taAverage`, `aiAverage`, `paperGap`, `flaggedQuestionCodes`;
- `questions`: per question `sampleSize`, `taAverage`, `aiAverage`, `averageGap`, `threshold`, `flagged`;
- `flaggedPapers`: keyed by question code, the papers behind each flag, largest gap first, with both points and the AI's reasoning;
- `largestGaps`: the 3 largest single-answer gaps, on the worst flagged question (or anywhere when nothing is flagged), with the transcription, both points and the AI's reasoning;
- `papers`: every paper the TA graded, with TA/AI points per question.

Returns 404 for an unknown TA. A TA with no AI-graded papers yet gets empty lists.

### `GET /courses/:id/stats?examId=` ✅ (owner)

Built by `buildCourseStats` in `backend/src/reports/course-stats.ts`, from AI-graded papers. With `examId` (404 if it isn't in the course) the KPIs, leaderboard averages, pass/fail, distribution and rubrics cover that exam only; the trend always covers every exam.

- `course` (with `leaderboardVisibility`), `exams`, `focusExamId`;
- `trend`: per exam with graded papers, `averageGap` = mean over TAs of |TA paper gap|, `papers`, `flaggedTas`;
- `headline`: `first` and `last` exam, relative `change`, `improvingEveryExam`, `tasCloser` / `tasCompared`, `tasFurther` (names);
- `kpis`: `papersSubmitted`, `aiGraded`, `averageGap` (latest or focused exam), `flagsRaised` and `flagsByExam`, `medianMinutes` (scan to submit);
- `atStake`: papers where TA and AI disagree on pass/fail, largest gap first (`failsWithTa`);
- `leaderboard`: per TA `averageGap` (paper-weighted mean |paper gap|), `direction` (`stricter` / `lenient` / `even`), `sinceFirst`, `flags`, `medianMinutes`, `history` per exam, `badge` (`closest`, `improved`, `fast`);
- `distribution`: 10 bins out of 10 (TA and AI), `passMark`, `passedTa`, `passedAi`, averages;
- `questionsToTighten`: top 3 questions by spread (most lenient − strictest TA average gap, TAs with ≥ 3 papers), with the `outlier` when one TA is far from the rest.

### `GET /courses/:id/activity?limit=` ✅ (owner)

`{ activity: [{ id, type, createdAt, actor, ta, member, paper: { id, studentId, status }, exam, questionCode, averageGap, aiResult: { gap, mostlyCode, largestGap }, error }] }`, newest first, `limit` 1–100 (default 20). Names and exams referenced in the payload are resolved; `aiResult` is filled for `AI_GRADED` entries.
